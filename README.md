# embedded-devops-ch06-servers

## Services in docker-compose

The stack in `docker-compose.yml` runs four services on a shared `stack-net` bridge network:

| Service | Image | Purpose |
| --- | --- | --- |
| `signserver` | `keyfactor/signserver-ce:7.3.2` | Code-signing server; exposes AdminWeb/Client Web on `8081` and HTTPS on `8444`. |
| `ejbca` | `keyfactor/ejbca-ce:9.3.7` | Certificate Authority (ManagementCA); admin UI on `8082` and HTTPS on `8445`. |
| `runner` | `ghcr.io/actions/actions-runner:2.336.0` | Self-hosted GitHub Actions runner; registers against the repo from `.env` and presents a client cert to SignServer. |
| `enroll` | `python:3.12-slim` | Device-enrollment HTTPS service on `9443`; devices POST a CSR over mTLS and get a ManagementCA-issued cert back. |

Persistent data lives in named volumes (`ejbca-data`, `signserver-data`, `runner-data`). The runner and enroll services need certs generated by the scripts before `docker compose up -d` will work.

## Scripts (in the scripts folder)

Numbered, ordered setup steps. Run all of them with `bash scripts/setup.sh`, or run individual steps:

- `00-check-prereqs.sh` — Preflight: verify tooling, Docker daemon + Compose, and ports.
- `10-start-stack.sh` — Start EJBCA + SignServer.
- `20-ejbca-superadmin.sh` — Enroll the EJBCA `superadmin` certificate and export the ManagementCA root.
- `30-issue-certs.sh` — Issue all service certificates from ManagementCA and prepare the keystores.
- `35-issue-enroll-certs.sh` — Enable the EJBCA REST API, issue the enroll-service certs, and start the `enroll` service.
- `40-wire-signserver.sh` — Recreate SignServer so it picks up the CA/TLS/worker mounts, then verify TLS.
- `50-configure-worker.sh` — Register the admin cert and create the SignServer crypto token + PlainSigner worker.
- `60-register-runner.sh` — Register the GitHub Actions self-hosted runner (human supplies the token).
- `70-verify-e2e.sh` — End-to-end verification: the runner signs through SignServer.
- `80-browser-trust.sh` — Browser (Chrome) trust guidance for the issued P12 + server.
- `90-uninstall.sh` — Uninstall: remove containers, data volumes, `keys/`, and `.env`.
- `95-healthcheck.sh` — Read-only health check: is the stack up, secure, and ready?

Shared helpers live in `scripts/lib/common.sh`.

## The enroll.py script (in the enroll folder)

`enroll/enroll.py` is a minimal, stdlib-only Python device-enrollment service (no dependencies).

**Flow:** ESP32 IoT devices present a reusable factory client cert over mutual TLS, `POST` a PKCS#10 CSR (the device keeps its own private key), and receive a per-device certificate issued by EJBCA's ManagementCA.

**Endpoints**

- `GET /health` — `200 "ok"` (no client cert required; used by the compose healthcheck).
- `POST /enroll` — `200` + PEM certificate on success; `403` without a client cert, `400` on bad input, `502` if EJBCA is unreachable.

**Configuration** comes from environment variables (never hardcoded), set in the `enroll` service in `docker-compose.yml`:

- `EJBCA_API_URL` — base URL of the EJBCA REST API.
- `EJBCA_CLIENT_CERT` / `EJBCA_CLIENT_KEY` — admin client cert/key used to authenticate to EJBCA over mTLS.
- `EJBCA_CA_NAME` (ManagementCA), `EJBCA_CERT_PROFILE` (ENDUSER), `EJBCA_EE_PROFILE` (EMPTY), `EJBCA_EE_PASSWORD` — the CA and profiles used for enrollment.
- `SERVER_CERT` / `SERVER_KEY` / `CA_BUNDLE` — this service's TLS cert/key and the CA bundle used to trust both device client certs and the EJBCA server.
- `LISTEN_PORT` — listen port (default `9443`).
